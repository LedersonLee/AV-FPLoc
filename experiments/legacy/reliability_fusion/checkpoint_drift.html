128→64 · Best→Last에서 성공을 잃는 이유

입력58 · frozen logit 회귀 supervision · seed42/43 · Train12 / Val3 · 재학습 없음 · Test 미사용

Best는 같은 Val로 선택한 checkpoint입니다(seed42 ep6, seed43 ep5). Last는 ep40이며 조기 종료하지 않았습니다. 아래 분석은 원인 후보를 좁히는 사후 진단이지, 새로운 loss나 입력이 더 좋다는 검증은 아닙니다.

1. 결론과 해석 범위

가중치가 바뀌는 동안 MAP는 연속 이동하지 않고 후보 사이에서 갑자기 바뀝니다. 따라서 작은 w 변화라도 Recall이 바뀔 수 있습니다. 성공 구간·GT 안전 여유·아래 target 관계는 분석에만 사용하며 MLP 입력에는 없습니다.

2. 같은 checkpoint의 Train / Val 비교

Recall 단위 %. Joint = XY≤1m AND yaw≤30°. loss는 supervised query 전체에 대해 checkpoint를 고정해서 다시 평가한 logit MSE입니다. 모든 쿼리는 Recall 분모에 들어가지만, 기존 21점 가중치 grid에서 성공하는 점과 유효 interior target이 있어야 회귀 loss에 포함됩니다. 따라서 loss 제외가 연속 가중치에서의 성공 불가능을 의미하지는 않습니다.

3. Best→Last 직접 전이

이 표의 Repair/Harm 기준은 Best입니다. Last 성공 수−Best 성공 수 = Repair−Harm. loss↓ Harm은 해당 쿼리의 logit MSE가 줄었는데도 Best의 성공을 잃은 경우입니다. 전체 loss 감소와 다른 집단의 Recall 하락을 혼동하지 않도록 분리합니다.

기존 고정 w=.1 대비 Harm과의 관계

4. 성공 구간을 어떻게 벗어났나?

인접한 성공 구간은 합쳐서 연결 성분으로 계산합니다. 이탈 경계는 Best가 속한 성공 구간의 끝입니다. Last까지 모델 파라미터가 실제로 거친 경로를 복원한 것은 아니며, 두 checkpoint의 출력값 사이 관계입니다.

Harm은 계속 성공한 집단보다 Best의 안전 여유가 작고, Val에서는 출력 변화도 더 컸습니다. 낮은 안전 여유는 성공 판정의 정의와 직접 연관된 사후 통계이며, 모델이 추론 시 알 수 있는 신뢰도 지표라는 뜻은 아닙니다. 위/아래 양방향 이탈이 있어 acoustic 가중치를 일괄 낮추는 것으로 모두 해결되지는 않습니다.

Δloss 기여는 집단의 loss 변화 합 / 해당 split 전체 supervised query 수입니다. 집단별 기여를 더하면 전체 Δloss와 같습니다. 안전 여유는 Best w에서 가장 가까운 성공 구간 끝까지 거리입니다. GT 사후 값입니다.

5. 점 목표와 성공 집합이 어긋나는 사례

초록 띠는 실제 Joint 성공 구간, 곡선은 학습한 점 목표에 대한 logit MSE입니다. 곡선의 바닥 한 곳이 target이지만, 성공 구간은 여러 조각일 수 있습니다. 파랑 Best → 주황 Last, 보라 target. 모델이 target에 가까워져도 실패 띠에 머무르거나 target을 지나 반대쪽 경계를 넘을 수 있습니다.

6. 학습 곡선

Train 곡선은 각 minibatch 업데이트 당시의 online 평균입니다. Val 곡선은 epoch 끝에 고정한 모델의 평균입니다. 정확한 Best/Last loss 비교는 위의 고정 checkpoint 표를 사용하세요. 서로 다른 2 seed를 유의성이나 원인 확증으로 해석하지 않습니다.
